# 01 - Memory Cache Basics

## دربارهٔ این پروژه

این پروژه، یک پیاده‌سازی مقدماتی و پایه‌ای از کش درون‌حافظه (In-Memory Cache) با استفاده از `IMemoryCache` در محیط .NET است. هدف اصلی، فراتر رفتن از دانش تئوریک و اندازه‌گیری عینی تأثیر کش بر روی کاهش زمان پاسخ‌دهی در یک سناریوی شبیه‌سازی‌شده می‌باشد.

## سناریو و پیاده‌سازی

مراحل انجام‌شده در این پروژه به شرح زیر است:

- **شبیه‌سازی پردازش سنگین**: ایجاد یک متد با تأخیر عمدی (با استفاده از `Task.Delay(2000)`) به‌منظور شبیه‌سازی عملیات زمان‌بری مانند کوئری سنگین پایگاه داده یا فراخوانی یک سرویس خارجی.
- **اعمال کش**: ذخیره‌سازی نتیجهٔ متد سنگین در حافظهٔ کش با استفاده از `IMemoryCache`.
- **اندازه‌گیری و مقایسه**: ثبت و مقایسهٔ زمان پاسخ‌دهی در دو حالت **بدون کش** و **با کش** جهت مشاهدهٔ تأثیر مستقیم آن بر روی کارایی.
- **بررسی استراتژی‌های انقضا (Expiration)**:
  - **Absolute Expiration**: تنظیم زمان انقضای مطلق که پس از آن، آیتم فارغ از تعداد دفعات استفاده، از کش حذف می‌شود.
  - **Sliding Expiration**: تنظیم زمان انقضای کشویی که با هر بار دسترسی به آیتم، زمان انقضای آن به‌اندازهٔ مدت‌تعیین‌شده تمدید می‌شود.
- **ثبت رویداد حذف (Eviction Callback)**: پیکربندی `PostEvictionCallback` برای لاگ‌گیری و بررسی دقیق زمان و دلیل حذف آیتم‌ها (از جمله Expired، Removed، یا Capacity).
- **مدیریت ظرفیت (اختیاری)**: بررسی پارامترهای `SizeLimit` و `Size` برای درک نحوهٔ کنترل حجم حافظهٔ تخصیص‌یافته و جلوگیری از مصرف بی‌رویهٔ منابع.

## مفاهیم کلیدی

- درک نحوهٔ کارکرد داخلی `IMemoryCache` و حوزهٔ کاربرد آن (مناسب برای برنامه‌های تک‌نمونه‌ای / Single-Instance).
- تمایز عملی بین `AbsoluteExpiration` و `SlidingExpiration` و کاربرد هرکدام در سناریوهای مختلف.
- آشنایی با محدودیت‌های Memory Cache در معماری‌های چندنمونه‌ای (Scale-Out) و ضرورت مهاجرت به راه‌حل‌های توزیع‌شده‌تر (که در پروژه‌های بعدی با Redis پیاده‌سازی خواهد شد).
